# Backend auf Java 25 (Temurin)

## Ziel

Das Backend baut und läuft mit Java 21. Seit 2025-09-22 ist Java 25 die neueste LTS-Linie. Mit
Harness 0.8.0 prüft `make deps` die Liste `stack` in `harness/config.yml`
(`harness/policies/versions.md`) und scheitert für `eclipse-temurin 21`:
`neuere LTS-Linie 25, LTS seit 2025-09-22`. Nach der Änderung bauen und testen der lokale Build
und CI das Backend mit Temurin 25, und der Eintrag `eclipse-temurin 25` besteht die Prüfung.

Lookup vom 2026-11-23 (`harness/scripts/stack-check.sh --latest eclipse-temurin`, Quelle
endoflife.date): `eclipse-temurin 25`, LTS seit 2025-09-22, Support bis 2031-09-30, neueste
Version 25.0.5.1+2. Linie 21: LTS, Support bis 2029-12-31.

## Scope

### Enthalten

- `maven.compiler.release` 25 in `backend/pom.xml`.
- Temurin 25 in `.github/actions/setup/action.yml`.
- Das Makefile wählt unter macOS JDK 25, wenn `JAVA_HOME` nicht gesetzt ist, und nur dann, wenn
  das gefundene JDK die Hauptversion 25 hat. Heute liefert `/usr/libexec/java_home -v 25` ohne
  installiertes JDK 25 das JDK 27 mit Exit-Code 0.
- `palantir-java-format` 2.103.0 in `backend/pom.xml`, weil 2.68.0 unter JDK 25 nicht läuft, und
  die Umformatierung von 21 Java-Dateien durch diese Version.
- Texte, die Java 21 als geltenden Stand nennen: `project-rules/backend.md`, `README.md`,
  `docs/architecture/overview.md`.
- ADR 0015.

### Nicht enthalten

- Harness-Update 0.8.0 und die Liste `stack` in `harness/config.yml`. Die Person bringt beides in
  einem eigenen Pull Request nach dem Merge dieser Spec auf `main`, dort mit
  `eclipse-temurin 25` (siehe Offene Fragen).
- Nutzung neuer Sprachmittel oder neuer APIs von Java 22 bis 25 im Quellcode.
- Upgrade von Quarkus, Maven (3.9 auf 3.10) oder anderer Abhängigkeiten.
- Historische Dokumente: `docs/umsetzungsplan.md`, ADR 0001 und die Specs 0001 bis 0046 bleiben
  unverändert.
